## Fonctionnalités présentes dans le code de la branche

- Modes TCP Client et TCP Serveur hérités de la version stable
- Sélection du transport TCP/UDP par YAML et interface web, sauvegardée en NVS
- UDP Client : RTU vers datagramme MBAP, réponse avec contrôle source IP/port, transaction ID et Unit ID
- UDP Serveur : datagramme MBAP vers RS485, réponse au client UDP d'origine
- ID Modbus RTU automatique ou manuel en mode Serveur
- Cache et diagnostics de trames, avec ressources graphiques intégrées

**Point de vigilance** : le mode UDP Serveur attend encore la réponse série de façon synchrone, ce qui peut retarder les autres traitements pendant un timeout.

## Configuration ESPHome de cette branche

```yaml
external_components:
  - source:
      type: git
      url: https://github.com/stephdust/my-modbus-rtu-tcp-gateway
      ref: feature/modbus-rtu-ip-udp
    components: [modbus_gateway]
    refresh: 0s
```

Exemple client UDP :

```yaml
modbus_gateway:
  id: gateway
  tcp_mode: CLIENT
  transport: UDP
  tcp_host: 192.168.1.71
  tcp_port: 502
```

## Étapes à la reprise

1. Sauvegarder la version fonctionnelle TCP 1.1.15 avant OTA.
2. Installer le nouveau firmware, vérifier l'interface et la persistance des paramètres.
3. Tester d'abord TCP Client et TCP Serveur (non-régression).
4. Tester UDP Client : lectures, écritures, réponses, timeouts, mauvaises sources et mauvais identifiants.
5. Tester UDP Serveur : ID RTU automatique/manuel, CRC, erreurs, cache, plusieurs clients et timeout.
6. Vérifier les libellés français/anglais, les logos et les icônes de l'interface.
7. Corriger les problèmes constatés sur cette branche uniquement, puis envisager une fusion dans `main` après validation.
